# 深读导航版规范（v24 · 2026-11-19 定稿）

> 适用：用户要「深读版 / 分层导航 / 知识星云 / 可折叠目录 / 星际巡游」等增强阅读体验时。
> 这是一个**可选分支**，不影响普通速读版（`build_deck.js` 完全不动，零回归）。

## 一、两条生成路径（如何选）

| 路径 | 生成器 | data 要求 | 产出 |
|---|---|---|---|
| 普通速读版（默认） | `scripts/build_deck.js` | 标准 data（无 `hn`） | 封面 + 平铺目录（每页30行）+ 观点页 + 洞察 + 尾页 |
| **深读导航版** | `scripts/build_deck_nav.js` | 带 `hn`/`tier`/`parent`/`children`/`refs`/`point` 的导航 data | 封面 + **可折叠树目录** + **知识星云页** + 观点页（层级徽标/面包屑/N导航）+ 洞察 + 尾页 |

判定：data 里 `ideas[].hn` 存在 → 导航版生成器自动启用树目录与星云页；否则走普通目录。
**两个生成器都要跑 `validate_data.py` 校验。**

## 二、数据构建（三步）

1. **先做深读版 data**：按 v21 四层逻辑提炼 3–5 倍于速读的观点数，落盘 `D:/WorkBuddy/[主题]_深读_data.json`。
2. **写分组 map**（`[主题]_map.json`）：人工判定三层树——核心→分层→基础。编号用深读 data 的原始 `no`。
   ```json
   { "groups": [
       { "core": 1, "label": "价值与货币", "point": "商品二因素",
         "layers": [ {"no": 2, "foundations": [32,81]}, {"no": 3, "foundations": [33,77]} ] }
   ] }
   ```
   - 核心数量因书而异（理论巨著 5 个，结构简单的书 3 个亦可），不强求固定。
   - `label` = 核心主题短名；`point` = 核心论点短词（用于星云悬停）。
   - **分组必须覆盖全部观点、无重复**，脚本会强校验。
3. **构建导航 data**：
   ```
   python SKILL/scripts/build_nav_data.py "<深读data>" "<导航data>" --map "<map.json>"
   ```
   脚本做：树遍历重排编号 → 注入 `tier/parent/children/coreNo/coreLabel/hn/point/refs` → 重映射 links 里的 `#N` → 更新 meta。
   - 也可省略 `--map`：若深读 data 每条已有 `tier`/`parent` 字段，脚本直接推断。
   - 层级编号：**核心 i.0 / 分层 i.j / 基础 i.j.k**（i,j,k 从 1 起）。

## 七、历史教训（避免踩坑）

- 重排编号后，`parent/children/coreNo` 必须一起做 old→new 映射，否则树断裂、关联只剩序号。
- 生成器 JS 写在 Node 大模板字符串里，内部 JS 的反引号与 `${}` 必须转义为 `` \` `` / `\${}`，否则 `node -c` 报 `Unexpected token`。
- 目录常量 `TOC_ROWS_PER_PAGE/TOC_COLS/TOC_PER_COL` 在改目录分支时不要误删。
- 星点密集时逐节点 mouseenter 会命中错误节点，必须用最近距离算法。
